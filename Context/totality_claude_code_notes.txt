ECONOMY SYSTEM - CREDITS (FULL REDESIGN)
----------------------------------------------------------------

CURRENCY SYMBOL: ₵ (C with bar through it)
- Used in UI as: ₵1000, ₵500 etc.
- Cyan C with circular ring emblem as the visual icon
  (not just a plain letter, has depth and feels like an official currency)

OLD SYSTEM (being replaced):
- Multi-denomination coins (Copper/Silver/Gold)
- Right-clicking coins auto-deposited to wallet
- WalletComponent tracked three separate values

NEW SYSTEM:
- Single unified credit balance stored as one integer in player component
- Physical coins stay as loot items but do NOT auto-deposit
- Player must visit Banker NPC to exchange physical coins for credits

PHYSICAL CREDIT ITEM (ONE ITEM, DYNAMIC VISUALS):
- Registry name: totality:credits
- One item with internal amount component: amount: [value]
- Visual tier changes based on amount (handled by model predicate system):

  Tier 1 — Credit Chip
  Amount: 1–9₵
  Visual: single octagonal chip
  Use: tiny loot, small change, weak mob drops

  Tier 2 — Credit Stack
  Amount: 10–99₵
  Visual: 2-3 chips stacked or scattered
  Use: starter quest rewards, daily quests, common loot

  Tier 3 — Credit Pile
  Amount: 100–999₵
  Visual: larger pile of chips
  Use: dungeon loot, quest rewards, merchant withdrawals

  Tier 4 — Credit Card
  Amount: 1,000–9,999₵
  Visual: dark card with cyan ₵ symbol
  Use: large quest rewards, rich NPCs, expensive trades

  Tier 5 — Encrypted Credit Card
  Amount: 10,000₵+
  Visual: premium glowing card, more cyan/gold detail
  Use: boss rewards, bank withdrawals, late-game loot

- Display name changes with tier (e.g. "Credit Pile", "Credit Card")
- Tooltip always shows: Value: [amount]₵ / Physical currency / Drops on death

STACKING BEHAVIOR (IMPORTANT):
- Credits do NOT stack normally (different amount components)
- Instead: credits MERGE when picked up
  Example: Credits 75₵ + Credits 25₵ picked up = Credits 100₵
  Visual updates automatically from Stack to Pile
- Max per item slot: 10,000₵
  If player has more, creates a second Credits item
  Example: Credits 10,000₵ + Credits 2,450₵ as two separate items

DEPOSIT BEHAVIOR:
- Banker/ATM checks all totality:credits items in inventory
- Reads their values, removes/reduces them
- Adds total to account balance
- Example: Credits 75₵ + Credits 500₵ → deposit all → account +575₵

WITHDRAWAL BEHAVIOR:
- Player chooses amount
- Receives one Credits item with that amount
- Visual tier assigned automatically based on amount
- Example: Withdraw 750₵ → receive Credits item (Credit Pile visual)
- Example: Withdraw 2,000₵ → receive Credits item (Credit Card visual)

ITEM VALUE SYSTEM:
- Each Totality item has base value defined at registration
  Example: ItemValue.of(1000) on item register
- Vanilla items: separate JSON mapping minecraft items to base values
  Example: { "minecraft:iron_sword": 800, "minecraft:diamond": 2000 }
- Items without defined value: either untradeable or fallback calculation
  based on rarity/material tier
- Sell price = percentage of base value (default 50%)
- Charisma or relationship can modify buy/sell rates

ITEM TAGS FOR TRADING:
- totality:sellable — accepted by any merchant
- totality:shady_only — only shady dealers accept
- totality:stolen — flagged as stolen; normal merchants refuse;
                    shady dealers accept at worse rate
- Future: stealing/pickpocketing system sets stolen tag automatically

DIMENSIONAL CURRENCIES:
- Different dimensions drop different physical currency items
- Examples: Septims (Skyrim), Ryo (Naruto), Zeni (Dragon Ball),
            Dollars (modern dimension), etc.
- All convert to ₵ credits via Banker or Value Exchanger NPC
- Value Exchanger: shadier alternative, worse rates, operates in
  locations Banker doesn't (inside dungeons, gates)
- Currency type as environmental storytelling:
  finding Ryo as drop = you're in a Naruto dimension

ECONOMY SYSTEM - BANK ACCOUNT
----------------------------------------------------------------

ACCOUNT TIERS:
- Basic Account:
  Free, opened at first Banker visit
  Credit storage cap: ₵10,000
  No interest
  Basic ATM access
  Basic transaction history

- Standard Account:
  Small one-time fee or quest requirement
  Storage cap: ₵100,000
  Player-to-player transfers enabled
  Extended buyback history

- Premium Account:
  Subscription (monthly credit fee)
  Unlimited storage
  Small daily interest on balance
  Free delivery from phone store
  Better exchange rates at Banker
  Priority merchant restocking notifications via mail

- Dimensional Account:
  Unlocked via specific gate or questline
  Can hold multiple currency types (Septims, Ryo etc.) + credits
  Exclusive dimensional store access

ACCOUNT vs PHYSICAL CREDITS:
- No account: credits are items in inventory, drop on death if you die
- With account: credits stored safely, don't drop on death
- Both systems coexist; players choose how to manage money
- Trading screen can use either physical credits OR account balance

INVESTMENT SYSTEM (like Skyrim):
- Merchants have a credit pool cap (how much they can pay for items)
- Selling TO a merchant increases their pool beyond normal cap
- Investment options to make increase permanent:
  Option 1: Speech/Charisma mastery perk
  Option 2: Good enough relationship with that merchant
- Investment costs a one-time credit fee
  (e.g. ₵500 for Novice, ₵2000 for Master)
- Without investment: pool resets on restock timer
- With investment: permanently raised pool

ECONOMY SYSTEM - MERCHANT TRADING
----------------------------------------------------------------

SHOP JSON STRUCTURE:
{
  "shop_id": "blacksmith_novice",
  "credit_pool": 500,
  "restock_days": 3,
  "accepts_tags": [
    "totality:weapons",
    "totality:armor",
    "totality:tools",
    "totality:ingots",
    "totality:crafting_materials"
  ],
  "sells": [
    { "item": "minecraft:iron_sword", "stock": 2 },
    { "item": "minecraft:iron_chestplate", "stock": 1 }
  ]
}

STOCK SYSTEM:
- Each merchant has limited quantity per item
- Resets on timer (restock_days)
- NPC inventory stored as actual component data on entity
  (not just JSON defaults, live values tracked separately)
- Supports pickpocketing later since inventory is real data
- Selling TO a merchant adds items to their real inventory
- Buyback reads from their real inventory

BUYBACK SYSTEM:
- Items sold to merchant persist in their inventory permanently
- Never reset on restock timer (unlike normal stock)
- Dedicated BUYBACK tab in trading screen
- Buyback price: FULL buy price (two confirmation screens = player's fault)
- In multiplayer: another player can buy your sold item before you buy back
  (inter-player trading through merchant as middleman)

TRADING SCREEN LAYOUT (mockup generated):
- Left: 3x4 item grid (item name above slot, price below in gold ₵)
- Right: Detail panel (large item icon, name, description, stats list,
         lore line at bottom)

- Bottom left: BUY tab / SELL tab / BUYBACK tab
- Bottom right: Green checkmark (confirm) + Red X (cancel)
- Selected item highlight: cyan border glow
- Affordable indicator: items player can't afford shown dimmed or red price
- SELL tab: filters player inventory by merchant's accepts_tags
- High value confirm popup: second confirmation for purchases above threshold
- Bulk buy/sell: slider + text input field, live price update as you drag
  Capped at: merchant stock available OR player credit balance OR item limit

ANVIL OVERHAUL
----------------------------------------------------------------

PLANNED:
- Intercept vanilla anvil interaction
- Instead of flat XP cost: trigger a Smithing skill check (d20 roll)
- Roll modified by player's Smithing skill level

OUTCOMES:
- Nat 1: repair fails, possible additional damage to item
- Nat 20: perfect repair, bonus durability or small enchantment bonus
- Normal success: standard repair
- Failure: partial repair or wasted materials
- Higher Smithing skill = lower success threshold = rarely fail at high level

BLACKSMITH NPC vs ANVIL:
- Blacksmith NPC: guaranteed success (you pay for reliability)
- DIY anvil: skill-gated, risky but free
- Creates meaningful choice between the two systems

BLACKSMITH REPAIR SCREEN (custom GUI via dialogue API):
- Left slot: item to repair
- Middle slot: ingredient (optional, offsets gold cost)
- Right slot: output with check/X overlay
- Hover tooltip: cost breakdown (base credits, ingredient discount, final price)
- Check = green if affordable, X = red if not enough credits/materials
- Ingredient offset: relevant material reduces credit cost
  Example: iron ingot reduces cost of repairing iron sword based on durability

BLACKSMITH UPGRADES (future):
- Second tab or dialogue option
- Pay extra to upgrade item material tier
- Only certain tiers available per Blacksmith tier
